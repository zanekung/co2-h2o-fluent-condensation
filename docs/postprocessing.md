# 使用 ANSYS EnSight 绘制凝结过程六联图

本教程说明如何把本案例的 Fluent 保存结果绘制成压力、温度、过饱和度、成核率、液相质量分数和液滴半径六幅云图。图中各面板表示同一时刻的空间分布，不是六个时间点。

案例定位是 **Student 环境下的学习与软件流程检查**。云图可用于理解模型输出和显示规则，但不构成实验验证、网格独立性或时间步独立性证明。

公开的 [中文图](../figures/figure2_cn.png) 和 [英文图](../figures/figure2_en.png) 采用**灰色掩膜并带说明文字**的版本：灰色表示不满足半径显示条件，不能解释成半径为零。它们是 ANSYS 原生渲染的历史输出，没有使用 AI 生成场分布。

## 1. 软件、数据和公开包范围

历史后处理使用 Windows、ANSYS EnSight 2026 R1（26.1）、ANSYS 自带 Python 3.12.11、PyEnSight 0.11.0 和 NumPy 1.26.4。文字使用已安装的宋体和 Times New Roman。ANSYS 软件和字体不包含在本包中；开源许可证不替代这些软件的使用许可。

本包提供配套的 [最终 Case](../native/final-100000.cas.h5)、[最终 Data](../native/final-100000.dat.h5)、[压缩的最终单元数据](../data/final/all-cells-100000.csv.gz)、[UDF 源码](../udf/)和上述静态云图。CSV 对应第 100000 步、物理时间 0.01 s、30000 个单元，包含 39 列：单元导出序号、x/y 坐标和 36 个字段。

Case/Data 保留完整设置与原始保存场，通过 HDF5 对象语义复制清理机器路径；仅允许文本路径变更，数值数据集须逐集核对，不重新求解。四个配套 UDF 源文件同时位于 `native/`，供查看完整 UDF 模型或继续求解前在本机手动 Build/Load `libfuel`；没有分发原机器的动态库。原 Case 的 `udf/compile/files` 列表为空，源码位于同一目录不代表读取 Case 时会自动编译。清理版的实际软件读取状态见 [验证说明](validation.md)，不能把数值对比等同于 Fluent 已成功读取。

**EnSight 原生备份仍不包含在本包中。** 可以用配套 Case/Data 按本教程重新建立场景，无需为了查看保存场而重新计算。CSV 不包含完整网格拓扑、单元体积和边界面通量，不能单独恢复相同的原生喷管云图。Fluent 读取、编译和设置核对见 [使用教程](tutorial.md) 与 [手动设置](manual_setup.md)；本包不提供自动准备程序。

阅读 CSV 时应解压或使用支持 gzip 的读入方式，并去除列名两侧的空格。按字段名索引，不要假定导出行号等于 HDF5 内部单元编号。

## 2. 在 Fluent 中准备可追溯的输出

查看本包保存的结果时，先在工作副本中使用 `native/final-100000.cas.h5` 和同名 `.dat.h5`，不要 Initialize、调用准一维初场函数或 Calculate。只有需要自行重算或生成新输出时才执行下面的流程；新结果应放在独立目录并使用新的来源记录。

1. 完成计算后，记录步数、物理时间、Fluent 版本、网格单元数及 UDF 版本。先保存 Case 和 Data，再开始独立后处理。
2. 将匹配的 Case/Data 保存在专用工作目录，保留未经改动的原件。建议使用 ASCII 路径，并为文件记录 SHA-256；不要覆盖用于求解完整性核查的原文件。
3. 导出单元中心坐标及下表涉及的场量，保留原始 UDS 和 UDM。CSV 用于数值检查，原生云图仍由 Case/Data 读取。
4. 将求解结果与绘图工作目录分开。改变图例、筛选或视口不需要重新初始化、迭代，也不应为了获得某种图案去修改原始场。

不同保存时点的诊断字段可能略有差别。应明确每张图实际读取的是哪一对 Case/Data，不能把最后一行监测日志与随后保存的全部字段自动视为逐值相同。

## 3. 读取数据并核对变量

在 EnSight 中加载 Fluent HDF5 Case，并指定相匹配的 Data 文件。先只显示流体区域 `fluid-domain`，确认能看到整个二维流道，隐藏边界辅助显示。

如使用 PyEnSight，以下是已执行流程中使用的关键调用示例。它只示范加载与变量换算，不是本包提供的完整自动绘图入口。安装目录和文件路径由运行者配置。

```python
from ansys.pyensight.core import LocalLauncher

session = LocalLauncher(
    ansys_installation=ansys_installation,
    batch=True,
    timeout=100,
    do_not_start_ws=True,
).start()
session.load_data(str(case_path), result_file=str(data_path))
ensight = session.ensight

# 先确认并选中实际流体 part，再创建仅用于显示的变量。
ensight.part.select_begin(fluid_part_number)
for expression in (
    "P_kPa = Pressure_absolute / 1000",
    "Y_percent = UDM_18 * 100",
    "J_scaled = UDM_3 / 1e21",
    "R_nm = UDM_5 * 1e9",
):
    if ensight.variables.evaluate(expression):
        raise RuntimeError(expression)
```

这些变量名来自历史 EnSight 26.1 的 Fluent HDF5 读取结果。其他版本或读取设置可能显示不同名称，必须先核对变量列表与 UDF 字段含义，不能仅按序号猜测。压力使用**绝对压力**，不能将表压直接当作绝对压力绘制。

|面板|EnSight 历史变量名|公开 CSV 对应列|绘图量与色标|
|---|---|---|---|
|(a) 压力|`Pressure_absolute`|`absolute-pressure`|除以 1000，100–500 kPa|
|(b) 温度|`Static_Temperature`|`temperature`|320–390 K|
|(c) 过饱和度|`UDM_0`|`h2o-supersaturation`|0.5–3.6|
|(d) 成核率|`UDM_3`|`nucleation-applied-m3-s`|除以 10²¹，0–1.2 × 10²¹ m⁻³ s⁻¹|
|(e) 液相质量分数|`UDM_18`|`liquid-mass-fraction-beta`|乘以 100，0–2%|
|(f) 液滴半径|`UDM_5`|`droplet-radius-m`|乘以 10⁹；筛选后的区域使用 0–150 nm|

`UDM_3` 是实际施加的成核率，公开 CSV 还另存有 `nucleation-raw-m3-s`，两者不能随意替换。液相质量分数在图中记为 Y，在 UDF 中为 β：

\[
\beta=\frac{\max(L,0)}{1+\max(L,0)}.
\]

L 是每 kg 气体携带的液态水质量，不等于 β。其字段为 `Scalar_0` / UDS0，CSV 列为 `liquid-loading-kg-liquid-per-kg-gas`。

液滴数 N = `Scalar_1` × 10¹⁵ = UDS1 × 10¹⁵，单位为**个/kg 气体**；CSV 中未乘回缩放因子的列名是 `droplet-number-per-kg-gas-div-1e15`。N 再乘气相密度才得到个/m³的体积数密度，不能混淆。

## 4. 建立六个视口

采用 2×3 排列：第一行依次为压力、温度、过饱和度，第二行依次为成核率、液相质量分数、半径。

1. 从第一 case 的流体区域创建六份仅用于显示的副本，使每份只在对应视口可见。它们共享原始几何和字段，不是六套重新计算的模型。
2. 设置白色背景、正交投影，从 z 方向查看二维 x–y 平面。各视口使用同一相机和坐标范围，避免面板之间出现不同的缩放。
3. 用轴对称镜像显示上下两半流道。镜像只用于展示，不表示重新计算了一个完整上下对称网格。
4. 为便于观察细长流道，历史图将 y 相对 x 方向视觉放大约 2.6993 倍。若沿用该设置，必须说明图片的纵横比不是原几何比例；x 坐标仍为真实轴向距离，不能从图上量取真实直径。
5. 隐藏不需要的全局坐标三轴、边框和默认辅助标注；保留各面板的轴向刻度和色标。

以下归一化位置可用作重建历史布局的参考；原点在画布左下角，宽高均占整幅画布的比例：

|属性|设置|
|---|---|
|三列左边界 x|0.0648、0.3877、0.7105|
|上排视口下边界 y|0.7412|
|下排视口下边界 y|0.2486|
|每个视口宽度|0.2649|
|每个视口高度|0.1805|
|轴向显示范围|0–0.25 m|
|轴向刻度|0、0.05、0.10、0.15、0.20、0.25 m|

数值色标和文字应放在流道下方，避免遮挡云图。各面板色标按第 3 节设置，使用同一蓝—青—绿—黄—红配色顺序。重新计算得到不同范围时，应据真实数据调整色标并记录；不要为了匹配历史图而截掉新出现的有效值。

## 5. 半径图：先筛选，再按真实值着色

### 5.1 为什么需要单独处理

模型由液态载荷和液滴数的矩比估计平均半径：

\[
r=\left(\frac{3L}{4\pi\rho_lN}\right)^{1/3}.
\]

当 L 和 N 都很小时，这一比值仍可能产生很大的诊断半径。历史最终全场最大半径约 **780.768 μm，即 780768 nm**；它来自极小液态存量的数值尾部，不能当作主要液滴群的典型半径。

显示筛选只处理读图问题。半径参与生长率和源项计算，掩膜不会修复模型、负 UDS 或近空群数值判据，也不能证明这些尾值在整个求解过程中的影响已经排除。

### 5.2 在独立 case 中设置筛选

再次加载相同 Case/Data，建立第二 case，专用于半径显示。保持其他五个面板来自第一 case，避免筛选改变它们的可见单元。

有效条件为：

\[
L>10^{-12}\ \mathrm{kg/kg},\qquad N>0.
\]

等价的剔除条件为 `Scalar_0 ≤ 1e-12 OR Scalar_1 ≤ 0`。这里判断缩放前后的 N 正负号等价，但文档仍需保留正确单位。

历史 EnSight 设置使用以下四个单元过滤条件，结果取 OR 后剔除：

|条件|变量|比较|
|---|---|---|
|1|`Scalar_0`|小于 1e-12|
|2|`Scalar_0`|等于 1e-12|
|3|`Scalar_1`|小于 0|
|4|`Scalar_1`|等于 0|

在有效层建立 `R_valid_nm = UDM_5 * 1e9`，设置色标 0–150 nm，采用单元值的 flat 着色，避免跨筛选边界进行节点平均。给该层设置与其他视口相同的镜像和相机。

在有效层后放置一个全流道固定灰色底板，RGB=(0.9,0.9,0.9)，使剔除区域仍能显示几何轮廓。底板不绑定半径色标。为它添加独立说明：“灰色：低于有效液滴群显示阈值”或 “Grey: below droplet-population display threshold”。

**灰色不表示半径为零，也不能据此断言绝对没有液滴。** 它表示该位置不满足本图的显示条件。不要将掩膜外值改成零写回数据文件。

### 5.3 核对计数与阈值敏感性

历史结果通过上述条件后保留 15035/30000 个单元，双精度源数据中的有效半径约 7.227–129.792 nm，均处于 0–150 nm 色标内。EnSight 显示数组与双精度 HDF5 在末位有精度差异，不要求逐位相同。

|L 阈值|保留单元数|有效半径范围/nm|排除正液态存量/%|首个有效近轴单元中心 x/m|
|---:|---:|---:|---:|---:|
|10⁻¹²|15035|7.227062–129.792488|8.1630×10⁻¹¹|0.108500012|
|10⁻⁹|14026|12.818325–129.792488|6.0628×10⁻⁸|0.111833346|
|10⁻⁶|12731|17.840685–129.792488|8.0529×10⁻⁵|0.116166679|

这些是历史算例的离线检查值，不是新运行必须达到的目标。阈值属于公开的显示选择，不是实验验证的检测下限。提高阈值会改变首次可见位置，即使主要液滴区和最大值不变。

质量比例按 \(\sum\rho_gV\max(L,0)\) 计算，不能用单元数比例替代。CSV 本身不含完整的 V；精确库存检查应使用配套原生 Case/Data 的网格和保存场进行几何积分，或使用自行运行后保存的匹配文件。仅有 CSV 时只能复查计数与字段条件。

## 6. 定义阶段并绘制分区线

为了使区间划分可复查，本案例把阶段 II 定义为：**近轴成核率主峰中，包含最大值且 J≥0.05Jmax 的连续单元窗口**。

操作步骤：

1. 从 Case 网格中识别与 axis 边界相邻的单元，取实际单元中心并按 x 排序。历史网格中有 400 个这样的单元。
2. 读取对应的 J，找到最大值，再从主峰向左右寻找满足 5% 阈值的连续窗口。不能把其他孤立小峰并入该窗口。
3. 使用窗口首末单元在 axis 上的真实网格面端点作为边界，不通过外观拟合分区位置。
4. 将同一对 x 边界映射到六个视口，以白色竖向短虚线表示，并添加 I、II、III 标签。

历史窗口有 21 个单元，主峰中心 x=0.1208333454 m，边界为 **0.1166667 m 和 0.1236667 m**。图中以四位小数标为 0.1167/0.1237 m，形成以下区间：

|区间|范围/m|用于读图的含义|
|---|---|---|
|I|0–0.1167|膨胀与过饱和建立|
|II|0.1167–0.1237|集中成核主峰窗口|
|III|0.1237–0.250|成核衰减与液滴生长|

历史图保留“非平衡过饱和阶段”等过程名称，但 I 区并非处处 S>1，II 区外也不是 J=0。上述区间是可视化定义，不是普适物理分界、Wilson 点或全二维截面的相界。近轴单元中心位于 r>0，不是额外插值得到的几何轴线值。

使用配套原生 Case 可识别真实 axis 邻接关系；如果只读取 CSV，可以查看这些近轴样点附近的趋势，但不能仅凭 CSV 行号重建真实边界面拓扑。重新计算后应按自己的网格重新确定窗口，而不是强制沿用历史分区数字。

## 7. 文字、色标与导出

推荐图中文字如下；物理量与单位必须和字段表一致：

|中文|英文|
|---|---|
|(a) 压力 P/kPa|(a) Pressure P/kPa|
|(b) 温度 T/K|(b) Temperature T/K|
|(c) 过饱和度 S|(c) Supersaturation S|
|(d) 成核率 J/(10²¹ m⁻³ s⁻¹)|(d) Nucleation rate J/(10²¹ m⁻³ s⁻¹)|
|(e) 液相质量分数 Y/%|(e) Liquid mass fraction Y/%|
|(f) 液滴半径 R/nm|(f) Droplet radius R/nm|
|喷管轴线位置 x/m|Axial position x/m|

EnSight 原生文本对象支持分别设置字形、位置和大小。历史中文使用宋体，英文、数字及单位使用 Times New Roman。英文文本应检查上标 ²¹、负指数和单位间距；不要把普通数字简单拼接成错误的量纲。

历史图以约 **146.4 × 92.8 mm** 的物理显示尺寸校对字号。将图放进文档时保持相近尺寸；增加导出像素用于提高清晰度，不等于应扩大页面上的物理尺寸。不同平台、字体和抗锯齿设置可能产生细微差异。

完成后：

1. 检查六个场、单位和色标是否一一对应，图例和文字不与场分布重叠。
2. 检查灰色区域及其独立说明，确保没有被误标成零半径。
3. 先导出预览，再导出全尺寸 PNG。历史英文预览为 1268×804，中文为 2639×1673；全尺寸分别为 5072×3216、5278×3346。
4. PyEnSight 的历史导出调用为 `session.render(width, height, aa=4)`，返回的 PNG 由 ANSYS 原生渲染。保存返回字节即可，不需要外部拼图或位图补画。
5. 在自己的工作目录保存完整 EnSight 备份和上下文，保留关联文件及源 Case/Data。关闭会话后重新打开，渲染同尺寸预览并与保存前比较。

完整备份入口 `.ar` 需要它引用的 `.clientbkup` 和 `.serverbkup`；上下文 `.ctx` 也有配套文件。仅保存单个入口文件并不构成可复现归档。涉及中文原生文件时还需检查编码，不能盲目用另一种编码重写。

## 8. 显示修改历史

公开默认图采用灰色掩膜和可见说明，便于区分数值与显示规则。历史上还做过两个显示调整，保留其含义是为了说明它们没有产生新的计算结果：

- **蓝色填充。** 将灰底改为固定 RGB=(0,0,1)，并隐藏图内的掩膜说明。原始半径、L、N 和有效半径层没有改变，也没有补算或插值得到新的前段半径。由于这种蓝色与色标低端相同，单独传播会有“半径为零”的歧义，因此不作为本公开案例的默认展示。
- **分区虚线加粗。** 在后续显示版本中，保留分区线中心与间距，隐藏 120 根原细短线，用 240 个 EnSight 原生填充矩形绘制深灰描边和白色线芯；归一化宽度分别为 2.6/1268、1.3/1268。这个操作只改善缩图后的辨认度，没有更改场数据或阶段位置。本公开图仍使用已有灰色带说明版本，没有重新绘制一套组合版本。

历史检查确认补色前后有效半径数组不变，其他五个面板像素不变；虚线更新的像素变化仅位于分区线邻域。这些检查证明指定的显示修改范围，不等于模型验证。

## 9. 已有证据与尚未验证的事项

历史 EnSight 26.1 会话中，保存完整工程后恢复、关闭后在全新进程恢复，均得到与保存前字节一致的中英文预览。这是**当时环境下的恢复证据**。

本公开版包含路径清理后的完整 Case/Data、CSV、图像、UDF 与操作说明，但不包含历史 EnSight 备份。清理版在 Fluent 2026 R1 的实际读取状态为 **`NOT_VERIFIED_RUNTIME_BLOCKED`**：Windows 代码完整性策略在启动时拦截 `Qt5Widgets.dll`，读取测试未能开始。没有关闭或绕过该策略。详见 [验证说明](validation.md)。这不是文件读取成功或失败的证据，也不能用原私有文件的历史读取结果替代。以后即使读取成功，也不等于重新完成了 100000 步计算或重新生成全部六联图。

**公开版尚未在另一台机器上完成从原生文件到新计算、再到六联图的端到端测试；Fluent 2024 R2 仍未实测。** 不能把历史恢复记录扩大成公开版已通过移机测试或跨版本兼容保证。本文中的 API 示例和操作步骤也不是一个已发布并测试过的一键准备入口。

模型、网格、时间步、物性和边界条件的验证应单独进行。云图看起来平滑、数值有限、计算步数完成、图像恢复一致，都不能替代与独立实验或可信基准的定量对照。
